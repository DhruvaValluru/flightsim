## Per push: runner → synopsis → cross-check

**Runner.** One queue; a `pushed` that arrives mid-build waits. On
`P3 pushed <commit> letter=<L> boxes=<...>`: `git pull --no-rebase`, check out
`<commit>`, Windows builds if any, then build the engine only if the A4 stamp
says the cache is stale (one build per batch). Run every WINDOWS check for
the listed boxes in plan order, each through `phase3_event.py run`, output
saved under `runs/<id>/` and summarized in `docs/PHASE3_LOG.md`. For the D6
matrix, one cell at a time. Idempotent: a `pushed` for a commit already
checked is a no-op reply of the stored verdicts. Keep only the last passing
run per box on disk. Read the CI result for `<commit>` with the GitHub tools
(`actions_list`) into `gate_log_<L>.md`; CI green on ubuntu, windows and
macos is the "three operating systems" row.

**Only the checks the sheet names** (owner's rule, 2026-11-04). A box's
Windows run is exactly the check lines under that box in
`tasks/phase3_checklist.md`, plus the one or two steps its note marks
`needs_windows`. Nothing else: no `pytest -q` of the tree or of a test
file the box did not change (CI covers those), no re-running a box that
already has `verdict: PASS` for the same run unless a retry names it, no
second web run to "confirm", no extra headless flights, no engine rebuild
when the A4 stamp says the binary is current, and no exploratory runs to
characterise a failure beyond the one packet. A retry push re-runs only the
boxes it names. Boxes marked 🐍 (Python-only) get their one pytest file
and nothing more.

**Synopsis (script, then haiku only on failure).** Per box:
`docs/phase3/packets/<box>-synopsis.md` with the command, exit code, the
last 40 lines, and pass/fail.

**Cross-check (fable).** Opens `notes/<box>.md`, greps the box's verify
line from `tasks/phase3_checklist.md`, and compares the synopsis against the
note's goal, chosen approach and that verify line. It must quote the verify
line and the exact output line that satisfies it; no quote, no tick.
- PASS: tick the box in `tasks/phase3_checklist.md` (`[ ]` → `[x]`), write
  `verdict: PASS, run_id` into `state/<box>.json`, append the synopsis and
  the box's final diff to `sync_log_<L>.md`, commit, push, send
  `P3 verdict <box> PASS run=<id>`.
- FAIL: write `docs/phase3/packets/<box>-<n>.md` (box, expected per the
  note, what happened, exact error text, files involved), write
  `verdict: FAIL` into the state file, commit, push, send
  `P3 verdict <box> FAIL packet=<path>`.
- On a retry whose diff touches the pin, an ID band, a manifest version, a
  message id or a settings key, also send `P3 shared-value-changed <box> <what>`.
- `P3 machine-fix <box> <what>` from the Mac: fix the machine (cache, bake,
  material, import), re-run only that box, verdict as above.
