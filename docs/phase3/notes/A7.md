## approaches
- A (chosen): put the one-shot logic in `assets_pipeline/importer.py` (already "the one implementation") and call it from the three refusal sites. Single code path, testable with a fake `ensure_model`.
- B: call `scripts/import_aircraft.py main()` via subprocess from capture/generate. Rejected: extra process, output parsing, the script's exit code mixes skipped/failed.
- Staleness: mtime (chosen, matches plan wording) vs content hash recorded in the manifest. Hash is robust to git checkout/mtime noise but needs a converter change and a manifest version bump; mtime risk is a fresh clone re-importing once; mitigated because `assets/generated` is local output and a stale-only (not missing) case re-converts without the editor.
- Preview-time (`render_here`) provisioning vs render-time only: preview must stay quick and CI-safe, so chosen: render_here reports "will be imported on render" and does NOT import; the capture subprocess does the import. (Owner can overrule.)
