## approaches
A. platform.py reads toolchain.json at import (chosen). Keeps `UE_ENGINE_VERSION` importable as a module constant for every caller and test; one source of the pin on the Python side; the file sits at repo root found from `__file__`, no env var, no flag. Cost: an import-time file read and a hard failure if the file is missing (a named `toolchain.pin_unreadable` refusal).
B. Keep the literal and generate toolchain.json from it, or the reverse via a script. Two copies drift; the plan says "replacing the A2 literal". Rejected.
C. Lazy getter function `ue_engine_version()`; every caller changes. Touches many callers and tests for no gain. Rejected.
PowerShell side: (i) a single new function in ue_preflight.ps1 (chosen, the plan lists only that file); (ii) put it in ue_engine.ps1 so build_ue.ps1 can reuse it. Better reuse but widens the file list; offered as a note to Align. `Get-PinnedEngine` is left reading the uproject (B3 asserts the two agree); changing it is not in B2.
