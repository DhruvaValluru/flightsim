## approaches
- A. Compose components in `core/capture/objects.py` (`object_entries`/`assign_int_ids`) so the card, the manifest and the engine share one list (existing rule: "composed ONCE in Python"). Card.py only enriches with the extent and validates. Costs one file beyond the plan.
- B. Append components only inside `write_run_card`. Smaller diff to the plan's file list, but the manifest and `webapp/capture.py` would not see the same ints; the "one list" invariant breaks. Rejected.
- C. Widen the id pattern to `payload:tank_centre` (no instance) instead of `payload:<id>:0`. Rejected: schema edit with no gain; the existing pattern already admits `class:name:n`.
- Band: (i) fixed 64-127 for components, others 1..63 only when the primary has components (chosen: old runs and ids are unchanged; refusal is explicit); (ii) always reserve 64-127 (rejected: would newly refuse existing 64..255-object scenes); (iii) components numbered after everything (rejected: not a stable band, would collide with traffic growth).
Chosen: A + band (i).
