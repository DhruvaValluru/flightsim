## approaches
- A. Stores as extra UStaticMeshComponents on the aircraft actor, under MeshOrigin; stencil overridden per component; parent's alone pass = existing show-only actor (stores included for free); each component gets a ShowOnlyComponents pass. Trade-off: smallest change, stores move with the airframe and its attitude with zero extra transform code; needs a per-component stencil override and a component pointer on the labelled entry. CHOSEN.
- B. Stores as separate actors attached to the aircraft actor. Per-actor stencil works unchanged and `ShowOnlyActors` per component works, but the parent's pass must add the child actors by hand, the actor iterator loop would stencil them by actor, attachment teardown is more code, and traffic/primary lookups at :2745 have no actor source. Rejected.
- C. Parent alone pass = union of per-object passes composed in Python. No C++ for the parent pass, but it hides a union step in the verifier, makes `pixels_alone` for the parent depend on ordering, and splits the amodal depth test across two depth captures that can disagree. Rejected; the engine does it in one pass.
- D. Parent+children drawn in one pass (chosen with A) versus parent only: parent-only would leave the store out of the parent's amodal box, which the plan forbids.
