## approaches
- A. New standalone gate functions (chosen): `component_coverage` and `component_boxes` as separate `Check`s registered in the same list. Trade-off: two more report rows; but each has its own failure key and mutation guard, and a mutant failing coverage cannot be masked by a box failure. Matches how every other annotation gate is built.
- B. Fold component checks into `verify_box_vs_mask`/`verify_mask_integers_only`. Fewer rows, but plan names `component_coverage` as a gate and a combined check blurs which fault tripped; rejected.
- Export: (chosen) rely on taxonomy-driven categories and fix only supercategory/keypoint handling, vs. a separate component export path: rejected, it duplicates the class_id machinery and the plan says conventions are reused.
- Coverage test source: mask pixels (chosen, independent of the labels, so it catches a dropped record) vs. fraction_in_frame from labels (would pass when the record is dropped).
