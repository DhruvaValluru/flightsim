## approaches
- A (chosen): treat the gear as a component via the existing `gear_geometry` object patterns; add a `gear` ObjWriter beside "body" and the surface writers; manifest `components[]`. Why: smallest change, reuses the pattern list that already anchors the z origin, no new config vocabulary, and the gear z anchor stays on the same vertices. Cost: one landing_gear component (all wheels/struts in one box) rather than per wheel.
- B: declare the gear as a `surfaces` entry (:40, per-surface OBJ for animation). Reuses the existing writer split with zero convert.py change, but `surfaces` means articulated control surfaces (decision 6 says those are out) and would produce a surface asset the importer treats as moving. Rejected.
- C: one component per wheel (nose, left, right) with separate patterns. Better boxes per wheel, needs three patterns, three IDs, and gear_geometry has no per-wheel split today. Deferred; revisit only if the owner wants per-wheel boxes.
