## agreement
Shared with E1, E3, E5. Keys are lower_snake_case, no FLIGHTSIM_ prefix.
- File path rule: `settings.json` in the per-OS user data dir: mac `~/Library/Application Support/flightsim/settings.json`; windows `%APPDATA%\flightsim\settings.json`; other `${XDG_CONFIG_HOME:-~/.config}/flightsim/settings.json`. No env var chooses the path (tests set the module attribute `SETTINGS_PATH`). Missing, empty (0 bytes) or `{}` file = all defaults. Unreadable JSON refuses by name `settings.unreadable: <path>: <why>` (never silently reset).
- Defaults (empty file, empty env): `google_tiles` true, `google_tiles_key` "", `llm_key` "", `llm_model` "", `render_quality` "measure", `capture_passes` [], `weather_backend` "procedural", `rain_gain` 4.0, `rain_style` "cinematic". Tiles and storm are on; `FLIGHTSIM_GOOGLE_TILES=off` is still the off switch.
- GET /settings returns `{"settings": {<every key>: value}, "defaults": {...}, "readonly": {"engine": "5.7.4", "cesium_status": {"ok": bool, "name": "cesium_for_unreal", "version": "2.30.0"|null, "message": str}}, "env_override": {<key>: "<ENVNAME>", ...}, "missing": [{"key","message"}], "path": str}`. Secrets: GET returns `google_tiles_key` and `llm_key` as stored (single-user local app; E3 shows them in password inputs); they are never logged. PUT /settings takes `{"settings": {<partial keys>}}`, validates each key against the E1 table (unknown key or bad value = 422 `settings.<key>: <why>`), merges, writes atomically (tmp + os.replace), returns the GET body. Read-only keys (`engine`, `cesium_status`) in a PUT = 422.
- Env override record in the run: run record gains `env_override`: `[{"key": "google_tiles", "env": "FLIGHTSIM_GOOGLE_TILES", "value": "off", "settings_value": true}, ...]` (secret keys record `"value": "<set>"`); the status line text is `env override`.
- Read-only sources: `engine` = `core.util.platform.UE_ENGINE_VERSION` plus `TOOLCHAIN["engine"]["patch"]` (toolchain.json, B2; the same pin ue_preflight.ps1 checks); `cesium_status` = new `cesium_status()` reading `TOOLCHAIN["cesium_for_unreal"]` and probing the engine Marketplace plugin (mac: not installed = named message).
- E3 field names: `google_tiles_key`, `cesium_status`, `engine`, `render_quality`, `llm_key`, `capture_passes`.

## goal
**Do:** `settings.json` in the user data directory is the only source for the UI items, behind `GET/PUT /settings`. Environment variables become developer overrides, recorded in the run as `env override`. The owner's defaults stay: tiles on, storm weather on.
**Verify:** an empty file and an empty environment give the documented defaults, and `FLIGHTSIM_GOOGLE_TILES=off` is still honoured.

## approaches
A. Settings file read lazily by each consumer through one `effective()` (chosen): env wins, then file, then default; no mutation of os.environ; each consumer change is a one-line swap. Easy to test with empty env.
B. At server start, export file values into os.environ so no consumer changes. Smallest diff, but then env and file are indistinguishable, so `env override` cannot be recorded, and a PUT needs to re-export. Rejected.
C. Settings in the SQLite/registry store. Heavier, plan says a JSON file. Rejected.
Key-to-render: pass via `env=` on the Popen (chosen) versus writing the key into render.json (leaks a secret into run folders; rejected).
