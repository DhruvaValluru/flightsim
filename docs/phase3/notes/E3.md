## agreement
Same block as docs/phase3/notes/E2.md `## agreement` (path rule, GET/PUT /settings shape, key names, `env_override` run record, read-only sources). Panel fields (exactly six, in this order): `google_tiles_key` (password input, writes via PUT), `cesium_status` (read-only, from GET `readonly.cesium_status`), `engine` (read-only, `readonly.engine`), `render_quality` (select measure|beauty), `llm_key` (password input), `capture_passes` (slot reserved: `<div id="settings-capture-passes">`; E5 owns the three checkboxes normals/flow/amodal and the capture.py read). ## goal
**Do:**
- Show at most six fields: tiles key, Cesium status, engine (read-only, from preflight), render quality, LLM key, and the extra passes.
- Everything else goes under "Advanced" or is removed.
- A missing required item shows as a named, fixable message.
**Verify:** a headless-Chromium page test sets the key, reloads, and finds it persisted.

## approaches
A. Separate `settings.js` module mounted in index.html, server rendered JSON via GET /settings (chosen; the plan lists it, same shape as D4).
B. Inline the panel in index.html. Larger index.html, no separate test target. Rejected.
C. A separate /settings.html page. Fewer layout clashes, but the plan puts it in index.html and "reload" persistence is clearer in one page. Rejected.
Test harness: reuse the node+Playwright pattern of test_route_page.py (chosen; no new dependency) versus pytest-playwright (new pip dependency, decision_needed) versus a jsdom/node-only test (does not use Chromium, weaker against the Verify line).
