## what the Windows runner records (machine: windows)
One row per machine under a new `## Letter F` section of `docs/PHASE3_LOG.md`, table `| machine | preflight | run id | verify | wall time | hash |`:
- machine: the A1 row name (engine laptop / reviewer / third);
- preflight: the last line of `scripts\ue_preflight.ps1` (exit 0, or the `toolchain.<tool>_mismatch` name);
- run id: the run F1's `test_demo_page_end_to_end` created (`runs/webapp/<run_id>`);
- verify: `verify PASS` when `GET /runs/<id>/verify.json` has `failed == 0` and `payload_boxes_cover_pixels == []`, else the failing check names;
- wall time: pytest's reported duration of the one test;
- hash: `sha256` of `toolchain.json` followed by `requirements.lock` (one digest over the two files concatenated in that order; the same command on every machine).
The Windows session writes row 1 after F1's step 5 passes on the engine laptop, from a fresh clone of the pushed commit (`git clone`, double-click `Launch FlightSim.cmd`, `READY`, then the F1 test).
