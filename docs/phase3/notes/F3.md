## guide outline (what docs/GUIDE.md states, in this order)
1. **What this is** (two sentences): a flight simulator that films an aircraft over real terrain and labels every picture with boxes around the aircraft and its payload.
2. **What to open**: double-click `Launch FlightSim.cmd`. The window shows seven steps (install, preflight, build, materials, aircraft, bake, server) and ends with `READY`; the browser opens by itself. A second launch says `up to date` for the steps already done. If it stops, the last line names the step and the reason; `logs/launch.log` keeps it.
3. **Once, the first time**: open Settings (the gear). Six items: Google tiles key (paste it once; the ground is drawn from Google's 3D tiles and a run without the key says so by name), Cesium status and engine (read-only, shown from the installed tools), render quality, LLM key (optional: without it a built-in parser reads the prompt), extra passes (Normals, Flow, Amodal). Nothing else is needed; the rest is under Advanced.
4. **What to choose**: Environment (Desert = Grand Canyon, Forest = Yosemite). Press Capture. With nothing typed the run is the A-4 with its three stores, over the Desert, chase camera, six seconds, boxes on, storm weather. Typing a prompt (an aircraft, a place, a camera) and pressing Interpret first changes those; the J-11A is the other aircraft.
5. **What to expect**: the status line goes from queued to flying to rendering to done (a first run over a new place prepares the terrain once, minutes); the clip and the frames appear with their boxes; the checks are listed by name with PASS/FAIL.
6. **What the output contains**: Download the dataset gives `dataset.zip` in the format chosen (COCO by default; KITTI, WebDataset, YOLO, VOC): the images, one box per aircraft and one per payload store on every frame where it is visible (landing gear when stated), the per-camera manifest with the flight data, the verification report, and the dataset card saying what was flown and what was checked.
7. **When something is refused**: every refusal is a sentence naming what to change (a missing key: Settings; a place with no terrain yet: wait for the bake; a check that failed: its name on the run page). No terminal is needed for any of it.
