causes, checked on this machine:

1. `module Marketplace` and `module Plugins`: the script (line 110) collects
   every quoted `[A-Za-z]+` token in `FlightSimBridge.Build.cs` as a module
   name; `FindCesium` builds a path from the literals `"Plugins"` and
   `"Marketplace"` (Build.cs lines 65-67), which are not modules. Script
   defect: the module list should come from the `AddRange`/`Add` module
   lists only (or the two path words excluded).
2. `show flag Grain`: the script greps `(Grain,` (line 158) but the engine
   writes `SHOWFLAG_FIXED_IN_SHIPPING(1, Grain, SFG_PostProcess, ...)` at
   `Engine/Source/Runtime/Engine/Public/ShowFlagsValues.inl` line 52 on
   5.5 and line 54 on 5.7, so the pattern matches neither engine. Script
   defect: the pattern should be `, Grain,` (the other show-flag lines use
   the same `(1, Name,` form; they pass only because their patterns happen
   to be `(Cloud` etc. without the comma, so check them all).
   `FlightSimSky.cpp` needs no change (line 459 `Flags.SetGrain(true)` is
   valid on 5.5).
3. `module CesiumRuntime`: Cesium for Unreal is not installed for UE 5.5
   on this machine (only `UE_5.7/Engine/Plugins/Marketplace/Cesium…` 2.30.0,
   which dropped 5.5 support). The project's `FindCesium` treats it as
   optional (`WITH_FLIGHTSIM_CESIUM=0`), so the build passes, but Google
   tiles need it. The owner is installing Cesium for Unreal 2.28.0 (the
   last 5.5 release) for the 5.5 engine; the script's module check should
   accept a project-level `ue/Plugins/CesiumForUnreal` as well as
   `Engine/Plugins/Marketplace` (it already searches `$PLUGIN`, which is
   only the JSBSim plugin folder).
4. `Python was not found`: line 168 calls `python3`; on Windows that is the
   Store alias, not the venv. The check still printed `ok` afterwards, so
   it is cosmetic, but the script should use the venv interpreter when
   present (`.venv/Scripts/python.exe`), like the other scripts.
