## Step 2 · classification

Not the elevator accumulation (`FlightSimScenarioWorld.cpp:2650`): the
card has no route schedule, and the two host flights of the web run agree
on every FDM column. Two named causes:

1. **Plugin/config error makes the commandlet process return 1 although the
   flight is complete** (same as packet A5-2 cause 1): on 5.7 Cesium 2.30.0
   depends on the Water plugin, whose editor module logs an Error for the
   missing `WaterBodyCollision` collision profile; the editor returns 1
   when an error was logged. Fix: the profile in `ue/Config/DefaultEngine.ini`
   (A5 builder, in progress). The CLI refusal then no longer fires, and the
   refusal text still needs step 3's wording (Mac) so that when it does
   fire it names the exit code and the log's last lines.

2. **Host determinism fails on one column only.** `verify.json`
   `host_determinism`: `2 different flights across 2 host flights of one
   card (chase=efcf0aca6fdf, host_flight=c57ab8ac49f2)`. Comparing
   `host_flight/host_telemetry.json` (solve pass) with
   `frames/chase/host_telemetry.json` (render pass) column by column: every
   column is identical except `agl_m`, which differs on 38 of 220 samples
   from sample 26, max 27.6 m. `agl_m` is JSBSim's `position/h-agl-ft`
   (`FlightSimScenarioWorld.cpp:2466`), and in this plugin JSBSim's ground
   callback is a line trace against whatever the world has loaded
   (`UEGroundCallback.cpp:16-35` to `JSBSimMovementComponent.cpp:305-341`,
   object types WorldStatic, WorldDynamic, Pawn, Visibility). The solve pass
   (`-nullrhi`) and the render pass stream the Cesium tiles differently, so
   the ground under the aircraft differs for a few seconds while both
   flights (altitude, attitude, speed, position) stay bit-identical. The
   digest (`core/capture/verify.py:1456-1480`) covers every column, so it
   fails. Decision 12 (`decisions.md`): the ground callback must answer from
   the same surface in every pass of a card, the collision raster the card
   names (the manifest already says "physics ground is the heightfield
   raster"); a ue/ fix for the Windows builder, no change to the digest.

3. `mask_vs_geometry` FAIL on the same run (`chase/frame_0000.png
   aircraft:A4:0: the centre of the mask's box (626, 356) sits 13.7 px from
   the centre of the projected hull box (640, 357) -- 5.3 % of the 257 px
   hull span, tol 2 %`) is not A8's: the flights match, so the offset is
   between the drawn A-4 and the verifier's hull basis
   (`assets/generated/A4/mesh_manifest.json` v3, re-based on the CG). It
   lands on A12 (seven gates) and is recorded there.
