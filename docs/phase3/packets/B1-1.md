  `$ErrorActionPreference = "Stop"` (line 12) does not stop on a native
  command's non-zero exit (`git clone`, `pip install`, `python -c`), so a
  failed clone prints an empty "this install is at:" line, the pip stage
  fails on a missing lock, the verify import fails, and the script still
  reports success and prints the launch line. The step's own check ("exit 0")
  is therefore satisfied by a broken install, which is the opposite of what
  B1 is for. The installer must check `$LASTEXITCODE` after the clone/pull,
  the pip install and the verify import, and exit non-zero naming the stage
  (the same shape as `ue_preflight.ps1`'s refusals), so a cut clone or a
  hash mismatch stops it. The network reset itself is this laptop's (the
  retry is running).
