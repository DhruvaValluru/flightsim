# B2 packet 1 (Windows runner, run B-1 on UE 5.7, 2026-11-04)

box: B2 · One file lists every other tool's version (`toolchain.json`)

expected (sheet: "preflight prints `OK` per tool, and a wrong version stops
it"; note step 5: one `OK <tool> <version>` line for each of engine, msvc,
windows_sdk, cesium_for_unreal, ffmpeg, python, jsbsim (7 lines), exit 0;
steps 6-7: a wrong ffmpeg / windows_sdk pin exits non-zero by name).

what happened on the 5.7 laptop (`powershell -NoProfile -ExecutionPolicy
Bypass -File scripts/ue_preflight.ps1`, `UE_ROOT` at UE_5.7,
`runs/p3/A-2/B2-preflight.log`): six OK lines and one false mismatch, exit 1:

```
  toolchain engine                   OK engine 5.7.4 (CL 51494982)
  toolchain msvc                     OK msvc 14.44.35207
  toolchain windows_sdk              OK windows_sdk 10.0.26100.0
  toolchain cesium_for_unreal        OK cesium_for_unreal 2.30.0
  toolchain ffmpeg                   OK ffmpeg 9.0.2
  toolchain python                   OK python 3.12.10
  toolchain jsbsim                   toolchain.jsbsim_mismatch: not found, pinned 1.2.4
Preflight FAILED -- see above.
```

Steps 6 and 7 pass (`runs/p3/A-2/B2-preflight-ffmpeg.log`,
`B2-preflight-sdk.log`): `toolchain.ffmpeg_mismatch: found 9.0.2, pinned
9.0.1` and `toolchain.windows_sdk_mismatch: found 10.0.26100.0, pinned
10.0.22621.0`, both exit 1; `toolchain.json` restored.

cause (measured): jsbsim 1.2.4 IS installed in the venv.
`.venv\Scripts\python.exe -c "import importlib.metadata as m;print(m.version('jsbsim'))"`
prints `1.2.4` with exit 0. The reader in `Get-InstalledTools`
(`scripts/ue_preflight.ps1` around lines 236-290) runs

```
$jsb = Probe $venvPy @("-c", "import importlib.metadata as m;print(m.version('jsbsim'))") |
    Select-Object -First 1
if ($LASTEXITCODE -eq 0 -and $jsb) { $found.jsbsim = "$jsb".Trim() }
```

and in Windows PowerShell 5.1 the `| Select-Object -First 1` on a native
command's output stops the pipeline early, which leaves `$LASTEXITCODE` at
-1 even though python printed the version. Replicated in a bare session:
`Probe ... | Select-Object -First 1` gives `LASTEXITCODE=-1 jsb=[1.2.4]`,
while the same command without the pipe gives `[1.2.4] exit=0`. The python
version reader above it survives only because it tests the regex, not the
exit code. Fix: capture Probe's output into a variable first and read
`$LASTEXITCODE` right after the call (or test the captured value alone),
then take the first line.

files involved: scripts/ue_preflight.ps1 `Get-InstalledTools` (jsbsim
branch; the same pattern for python should be made robust the same way).
`scripts/*.ps1` is Windows push scope: the Windows builder fixes it; the
box's own check (step 5: 7 OK lines, exit 0; steps 6-7 still fail by name)
is the proof.
